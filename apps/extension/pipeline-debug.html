The old final message was incorrect

The previous extension version said “no policy pages needed full review” when analyzing === 0 and completed === found. But non-policy links increased completed immediately, and failed policy reviews did too.

The updated build replaces those counters with separate likely, queued, active, succeeded, and failed review counts.

It also retains each discovered link’s label, redacted destination, classifier result, and review state in the popup’s “Link decisions” disclosure.

Why the output looks like a few vague “claims”

“Reviewed 3 passages; 0 material point(s) passed evidence checks.”

This is the API’s per-document overview metadata, not a claim. It means three extracted passages were reviewed and zero drafted points passed source/citation and claim-support checks for that document.

“Hosting region can affect where agent data resides.”

This is a finding explanation. The underlying finding also has an implication and exact source quote. The updated popup now labels initial results as provisional, full results as verified, and includes the source URL, implication, and quote.

Results were keyed by URL, but the title often fell back to the generic API title Policy review. The updated popup uses the link label and a sanitized source URL, labels initial results provisional versus verified, and shows each finding’s implication and source quote.

A full review can finish successfully with zero verified findings. Each link gets its own fast/full stream: one URL can fail its initial fast scan while another URL succeeds. The timeline now identifies link-specific stage messages and retains recent checkpoints.

What this run’s messages mean

“Current page wasn’t classified as a policy”

TypeSafe judged the current title/URL insufficiently policy-like. Since the page body is checked only after a positive classification, a real policy page can be missed here.

“The initial AI scan failed”

The API emitted this generic error when the fast scan failed before returning its initial event. The exact cause—provider response, model configuration, credentials, parsing, timeout, or network—requires the backend exception log for that request.

“3 review errors”

Three failures were recorded across the old run. The updated diagnostics associate failures with a sanitized URL and identify whether classification, fetching, extraction, fast scan, or full review failed.

“Full review” marked done

The phase indicator is page-wide, not a per-document ledger. Another candidate may still have failed; inspect each URL’s outcome separately before treating this as an all-success result.

Candidate record (safe, useful fields)

Stable candidate ID, anchor label, normalized URL (with sensitive query values removed), same-origin check, classifier decision, confidence, and policy type.

Per-policy review record

Candidate ID and URL, extracted character/passage counts, fetch outcome, fast event outcome, full event outcome, elapsed time, verified finding count, and a request correlation ID.

Privacy boundary

Keep raw policy text and full citation excerpts out of routine logs. Show structured checkpoints in the extension; keep provider stack traces and request IDs in backend logs for diagnosis.
